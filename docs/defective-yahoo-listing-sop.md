# 不良在庫をヤフオク出品可能にする操作SOP

対象: 荷受け・検品担当者、村上さん
境界: この機能は出品準備までです。ヤフオクへの入力・下書き保存・出品は行いません。

## 初回だけ必要な準備（2026-08-16 完了済み）

1. 承認後のデプロイで `drizzle/0024_outbound_boxes.sql`、`0025_defective_yahoo_listing.sql`、`0026_inventory_v2.sql` の順に適用する。→ 本番DB適用済み。
2. 既存GASプロジェクトへ `gas/writeDefectiveRow.gs` を追加し、既存の認証済み
   `doPost` から `action === "writeDefectiveRow"` を同ファイルのREADMEどおり呼び出す。→ 適用済み。
3. GASの新バージョンを人間が公開する。既存の発送管理シートには触れず、初回実行時に
   新規作成される `不良在庫` シートだけを使う。→ 2026-08-16 バージョン12で公開済み。

**公開先のデプロイを間違えないこと。** このGASプロジェクト（発送管理スプレッドシート
`仕入れ候補8月` に紐づく）は**アクティブなデプロイを6本持っていて、それぞれURLが違う**。
サイトの `GAS_WEBHOOK_URL` が指しているのは1本だけなので、他のデプロイへ新バージョンを
公開してもサイトからは何も変わらない。2026-08-15にこれが起きて、コードは入っているのに
`不良在庫` シートが1枚も作られない状態が1日続いた。

どのデプロイが本番かは **Apps Script の「実行数」ページ**で分かる。`doPost` の実行行に
出ている「導入」列のバージョン番号が、サイトが実際に叩いているデプロイ。そのデプロイを
`デプロイを管理 → 鉛筆アイコン → バージョン: 新バージョン → デプロイ` で更新する。
この手順ならURLは変わらないので、Vercelの環境変数もサイトの再デプロイも要らない。

## 検品担当者の操作

1. 取引ハブの「荷受け」→「② 動作確認」を開く。
2. 対象商品のカードにある「ジャンク売」を押す（同じ行の「返品」と間違えない）。
3. 不良タグを1つ以上選び、必要なら不良メモを1行で入力する。
4. 「iPhoneで撮影・写真を選択」から、①全体、②不良箇所のアップ、③付属品込みの
   3枚を撮る。最大10枚。写真なしでも登録できるが、タイトルに `【写真未撮影】` が付く。
5. 「不良在庫として登録」を押す。検品処理はここで完了し、相場取得とシート更新は
   非同期で進む。

## 出品待ち一覧（スマホ）— `/inventory/yahoo-listings`

検品の場に限らず、**いま出せるものを全部ここで扱う。** サイドバー「ヤフオク出品」。

- **区分は2つ。** `ジャンク`（不良品。タイトルに【ジャンク】、説明は動作保証なし）と
  `不要在庫`（動作するが自社で要らない物。【ジャンク】を付けず、説明は「動作確認済・返品不可」）。
  相場キーワードにも区分が効き、**不要在庫では「ジャンク」を検索語に足さない**。足すと
  中央値が下振れして、自分から安く売ることになる。
- **在庫からまとめて入れられる。** 「在庫から追加」→ 商品名で検索 → 商品名の行にチェックで
  その名前の在庫を全台選択。一部だけ出したいときは、いったん全選択してから個体IDで外す。
  不良タグが要るのは `ジャンク` のときだけ。
- **写真は登録後に足せる。** 各カードの「写真を撮る・追加」。棚の前で撮る運用のため、
  登録の瞬間に写真が無くてよい。写真が付くとタイトルの `【写真未撮影】` が外れ、
  その場でシートを書き直す。
- **相場は取り直せる。** 「相場を取り直す」で検索キーワードを直して再取得する。
- **「未反映 N件をシートへ送る」を押すこと。** 登録直後のシート書き込みはレスポンスを
  返したあとに走るので、Vercelが関数を凍らせると途中で切れる。**GAS側は書けているのに
  サイトが「未反映」のまま残る**ことがある（2026-08-17に実測）。このボタンは1件ずつ
  待って送り直すので、押せば確実に揃う。まとめて登録したあとは必ず押す。
- **まとめ出品は区分をまたげない。** ジャンクと不要在庫を1出品に混ぜようとすると拒否される。
  相場も説明文も別物で、混ぜると説明文が事実と食い違うため。

不要在庫として出したものは、在庫一覧では「不良在庫」ではなく **「国内販売」カテゴリ**に入り、
`在庫_国内_{商品ID}` として1行できる。元の在庫は1減る。

## 在庫化した後で不良が分かった場合

1. 「在庫一覧」の該当行から個体を選ぶか、上部の入力欄へ7桁の個体IDをスキャンします。
2. 不良タグ・メモ・写真は荷受け時と同じ画面で登録します。元の通常在庫を1減らし、`在庫_不良_{商品ID}` の不良在庫を1つ作ります。
3. 箱に入っている個体は先に物理的に取り出します。`sealed` は出庫画面で「封を解く」、`shipped` は「追跡番号を解除」→「封を解く」の順です。直接の不良変更は理由付きで拒否されます。

## まとめ出品

1. 「荷受け」→「③ 確認」の「ジャンクまとめ出品グループ」で2個体以上を選びます。
2. 「1出品にまとめる」を押すと、定型文Bと単品中央値×台数を目安にしたまとめ用1行がシートへ追加されます。単品行は残ります。
3. 解除時は「グループを解除」を押します。シート行は削除せず「解除済み」として残り、人間入力4列も保持されます。

写真はサーバーでJPEG・長辺1600pxへ変換され、
`defective/{商品ID}/01.jpg` のように商品ID単位で保存される。変換できない写真は元データを
保存し、ログに警告だけを残して検品を止めない。

## 書き込み先（2026-08-18 変更）

出品行の正本は **スプレッドシート「ヤフオク出品」の `出品待ち` シート**。
発送管理の `仕入れ候補8月` とは別ファイルで、共有ドライブの中にある。

- 書き込みは**GASを経由しない**。サーバーがサービスアカウントでSheets APIを直接叩く。
  発送管理のGASとは無関係なので、こちらを直しても出庫の書き込みには影響しない
- 折り返しは付けない（`CLIP`）。説明文が長くても**行の高さは既定のまま**
- 商品IDを一意キーにした upsert。**人が入れる4列は範囲に含めない**ので、
  何度送り直しても消えない
- `仕入れ候補8月` に残っている古い `不良在庫` シートは使わない。消してよい

## 村上さんの出品準備

1. スプレッドシート「ヤフオク出品」の `出品待ち` を開く。
2. 写真、不良内容、検索キーワード、相場の「中央値」を確認する。上部サマリの平均ではなく、
   単品・個人出品だけに絞った中央値を主指標にする。
3. 検索語が外れていれば、取引ハブ「荷受け」→「③ 確認」の該当カードで検索キーワードを
   直し、「キーワードで相場を再取得」を押す。
4. 人間入力欄の「開始価格」「出品ステータス」「出品URL」「落札額」を入力する。この4列は
   サイトから再更新しても上書きされない。
5. 「出品タイトル案」と「出品説明案」を確認し、ヤフオクへ各1回ずつコピペする。開始価格を
   人間が決め、1円開始・3日・おてがる配送（ヤマト匿名・宅急便）・発送3〜7日・自動再出品の
   既存設定を確認して、人間が出品する。

## エラー時

- `写真なし`: 現物がまだあるなら撮影し直す。タイトルの警告が消えるまで出品しない。
- `該当なし`: キーワードを短く修正して再取得する。取得失敗でも他商品の処理は継続する。
- `シート未反映`: 「③ 確認」から再取得する。日次処理も未反映行を再試行する。
- 同じ商品IDの行が複数ある: 出品を止め、GASが商品ID列を一意キーにしているか確認する。
- 登録に失敗したら写真を撮り直す。前の写真はストレージに残るが無視してよい。

## 開発者向け

ブランチを切り替えたら、型検査やテストより先に `pnpm install` を実行します（`sharp` / `cheerio` の依存差分のため）。
