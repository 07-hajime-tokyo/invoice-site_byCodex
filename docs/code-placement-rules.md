# コードの置き場所ルール

SSOT整理（16領域）で作った分割構造を今後も保つためのルール。
新機能の追加・改修・バグ修正のとき、コードをどこに書くかはこの表に従う。
「どのファイルに何があるか」を探すときは `docs/file-map.md`（辞書）を見る。

## 基本原則（3つだけ）

1. **SSOT（真実は1箇所）** — 同じ計算・判定ロジックは1ファイルに1つだけ置き、
   使う側は import する。コピペで2箇所目を作らない（片方だけ直して事故るのを防ぐ）。
2. **1ファイル1責務** — 1つのファイルには1つの役割。
   厳密でなくていいが、「このファイル何をするもの？」に一言で答えられなくなったら分割のサイン。
3. **画面ファイルは UI の組み立てだけ** — `client/src/inventory/pages/*.tsx` に
   計算・判定・データ整形を直書きしない。ロジックは分割モジュール側に置く。

今回の整理（SSOT化・16領域）は「巨大ファイルにロジックが直書きされて誰も触れなくなった」
状態の解消なので、直書きやコピペを1回許すと元に戻り始める。そこだけ守れば細部はゆるくてよい。

## どこに置くか（判断表）

| 書きたいもの | 置き場所 | 例 |
|---|---|---|
| クライアント・サーバー両方で使う計算・判定 | `shared/` | 管理番号の変換、取引ステータス判定 |
| API エンドポイント（tRPC procedure） | `server/` の機能別ルーター | `tradeRouter.ts`、`server/inventory/zaicoRouter.ts` など |
| サーバー側の業務ロジック | `server/inventory/` 等の機能別モジュール（ルーターから呼ぶ） | `deliveryHistoryLabelRefs.ts`、`receiptAckRules.ts` |
| 画面のロジック（計算・判定・表示用整形） | `client/src/inventory/pages/<画面名>/` ディレクトリ | `purchase-registration/stockWaiting.ts` |
| 画面の UI 部品（コンポーネント） | 同じく `pages/<画面名>/` ディレクトリ | `delivery-history/InventoryDetailToggle.tsx` |
| 複数画面で使う UI 部品 | `client/src/components/` | ボタン・ダイアログ等の汎用部品 |

### 迷ったときの決め方

1. まず `docs/file-map.md` で**似た機能がどこにあるか**を探し、その隣に置く。
2. サーバーでもクライアントでも使うなら `shared/`。片方だけなら各側の機能別ディレクトリ。
3. それでも迷ったら、画面ファイルに直書きだけは避けて、新しい小さいファイルを作る方を選ぶ。

## やってはいけないこと

- ❌ `pages/*.tsx`（画面ファイル）にロジック関数を直接追加する
- ❌ `server/routers.ts` に procedure の中身を書く（ここは各ルーターを束ねる結線だけ。現在約50行を維持）
- ❌ 1ファイルに何でも追記して巨大化させる（目安: 役割が2つ以上になったら分割を検討）
- ❌ `shared/` に React や DB など片側にしか無いものへの依存を持ち込む
- ❌ 同じ計算ロジックをクライアントとサーバーに二重実装する（`shared/` に1つ置いて両方から import）

## 新しいファイルを作ったら

1. **ファイル冒頭に1〜2行の役割コメント**を書く（日本語でよい）
2. **`docs/file-map.md` に1行追加**する（該当セクションの表に「ファイル | 役割」）
3. ロジックなら隣に `*.test.ts` を置く（対象ファイルと同じディレクトリ）

## テストについて

- 新規・変更ロジックのテストは**普通のユニットテスト**（`*.test.ts`）で書く。
- `*-baseline.ts` + `*-baseline-source.txt`（旧モノリスの挙動凍結）は**リファクタ検証専用**。
  新機能のために新しいベースラインを作る必要はない。
- 仕様変更でベースライン比較テストが落ちた場合は、凍結ソース側を新仕様に合わせて更新する
  （やり方は `docs/file-map.md` の「ベースラインテストの仕組み」参照）。
- プッシュ前に `npm test`（ユニット）と `npm run test:regression`（DB回帰）を通す。
